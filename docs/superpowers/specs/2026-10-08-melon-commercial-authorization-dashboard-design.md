# melon 商业授权与数据看板设计

- 日期：2026-10-08
- 状态：功能与视觉方向已确认，待书面评审
- 依赖：[melon 图案管理 Web 应用设计](2026-10-08-melon-web-design.md)

## 1. 目标

在 melon 中为每张图案建立独立、可追溯的商业授权历史，并根据有效授权记录展示收入趋势和图库商业状态。

本设计坚持“图案是原子”：

- `Pattern` 是唯一业务主体。
- 一张图案可以拥有多条 `Authorization`。
- 不引入跨图案订单，也不把多张图案合并成一份授权记录。
- 授权记录只描述该图案的一次商业授权。

MVP 必须支持：

1. 普通单领域授权、领域独占和全局买断。
2. 客户名称、授权领域、人民币价格、授权日期和备注。
3. 授权新增、编辑、作废、恢复，以及图案未永久删除期间的有效/作废记录历史。
4. 图案级授权摘要、商业状态筛选和独立数据看板。
5. 浅色与夜间模式，采用已确认的“石墨靛蓝”视觉语言。

## 2. 已确认范围

### 2.1 授权粒度

- `Pattern 1 → N Authorization`。
- 普通授权和领域独占每条记录只对应一个领域。
- 全局买断不对应具体领域。
- 同一领域可存在多条普通授权，并可授权给不同客户。
- 不建立订单、合同或客户档案；客户名称直接保存在授权记录中。

### 2.2 金额与日期

- 币种固定为人民币。
- 金额必填，精确到分，允许为 `0`。
- `0` 元授权仍计入授权次数，但对收入贡献为零。
- 只记录授权日期，不管理开始日期、结束日期或到期提醒。
- 收入按授权日期确认，不管理收款状态、分期、退款或资金流水。

### 2.3 明确不做

- 不上传合同、聊天截图或付款凭证。
- 不建立 CRM、联系人、订单、发票或应收账款系统。
- 不统计图片修改频率。
- 不做多币种或汇率折算。
- 不做授权到期管理。
- 不提供授权记录的逐字段版本时间线；`ChangeLog` 用于同步事件，不作为用户可见的审计账本。
- 单独的授权记录不允许永久硬删除；取消或录错使用“作废”。图案永久删除是唯一例外，届时其全部授权记录随图案一起硬删除。
- MVP 不支持离线新增或编辑商业授权数据。

## 3. 授权领域

### 3.1 系统字典

首版内置以下系统领域：

1. 家居服
2. 日用百货
3. 口水巾
4. 家纺床品
5. 服装服饰
6. 婴童用品
7. 箱包鞋帽
8. 文具纸品
9. 餐厨用品
10. 家居装饰
11. 包装礼品
12. 数码配件

系统领域由产品维护，普通用户不能改名或删除。

### 3.2 自定义领域

- 用户可以创建和删除自己的自定义领域。
- 名称去除首尾空格后长度为 1–32 个字符。
- 同一用户的自定义名称大小写不敏感唯一，也不能与系统领域重名。
- 自定义领域不提供改名；需要变更名称时创建新领域并停用旧领域，避免历史统计静默改变。
- “删除”实际为归档：不再出现在新授权选择器中，但已有授权仍显示创建时的领域名称。
- 选择器支持搜索系统领域、用户领域和即时创建自定义领域。

## 4. 数据模型

所有主键使用 UUID，所有业务查询以会话中的 `ownerId` 为租户边界。

### 4.1 `AuthorizationField`

- `id`
- `ownerId`：系统领域为 `null`，自定义领域为所属用户
- `scope`：`system | custom`
- `name`
- `normalizedName`
- `status`：`active | archived`
- `createdAt`, `updatedAt`, `archivedAt`

数据库分别约束系统领域名称全局唯一，以及用户范围内自定义领域唯一。服务层额外阻止自定义名称与系统领域冲突。

### 4.2 `Authorization`

- `id`
- `ownerId`
- `patternId`
- `operationId`：用户范围内唯一，用于防止重复提交
- `kind`：`standard | field_exclusive | global_buyout`
- `fieldId`：全局买断为 `null`，其他类型必填
- `fieldNameSnapshot`：创建或变更领域时写入，保证领域归档后历史仍可读
- `licenseeName`：客户名称，去除首尾空格后 1–100 个字符
- `priceFen`：人民币分，PostgreSQL `bigint`，值大于等于 0
- `authorizedOn`：PostgreSQL `date`
- `note`：可选，最多 1,000 个字符
- `status`：`active | void`
- `version`：授权记录乐观并发版本
- `voidedAt`
- `createdAt`, `updatedAt`

索引至少覆盖：

- `(ownerId, patternId, status, authorizedOn desc)`
- `(ownerId, status, authorizedOn)`
- `(ownerId, fieldId, status, authorizedOn)`
- `(ownerId, kind, status)`
- `(ownerId, operationId)` 唯一

对有效记录增加部分唯一约束：每张图案最多一条有效全局买断；每张图案每个领域最多一条有效领域独占。

### 4.3 `Pattern` 扩展

`Pattern` 增加 `commercialVersion`，初始值为 0。每次新增、编辑、作废或恢复授权时都在同一事务中递增。

商业状态、累计收入和授权次数不作为可独立修改的字段保存，而是从有效授权记录计算，避免双份数据不一致。图库列表可以通过聚合子查询或专用只读查询返回摘要。

### 4.4 `ChangeLog`

授权、授权领域和 `Pattern.commercialVersion` 的变化写入现有 `ChangeLog`。这些事件用于多设备在线刷新和未来同步扩展，但 MVP 不接受来自离线 outbox 的商业数据写入。

## 5. 商业规则

### 5.1 普通授权

- 只允许对 `status = ready` 的图案写入授权。
- 必须选择一个有效系统领域或自定义领域。
- 同一图案、同一领域可以存在多条普通授权。
- 如果图案已有有效全局买断，则不能新增。
- 如果该领域已有有效领域独占，则不能新增。

### 5.2 领域独占

- 必须选择一个领域。
- 生效后，该图案不能在该领域新增任何类型的授权。
- 其他领域仍可继续授权。
- 已存在的同领域历史普通授权保留。
- 创建时若该领域已有历史授权，界面必须展示摘要并二次确认。

### 5.3 全局买断

- 不选择领域。
- 生效后，该图案不能新增任何授权。
- 所有既有历史授权保留，不因买断而被删除或失效。
- 如果图案已有历史授权，界面必须明确提示“买断仅锁定未来授权，不会消除已有权利”，并要求二次确认。

### 5.4 编辑、作废与恢复

- 客户名称、金额、日期、备注、授权类型和领域均可编辑。
- 改变授权类型或领域时，按新增记录相同的规则重新校验。
- 编辑时的互斥校验排除当前记录本身；编辑、作废和恢复同时提交授权 `version` 与图案 `commercialVersion`。
- 作废保留完整记录，但立即从有效授权、收入和商业状态中排除。
- 作废领域独占或全局买断后，相应未来授权限制立即解除。
- 恢复前重新执行全部互斥校验；若当前状态冲突，则拒绝恢复。
- 对已作废记录再次作废是幂等成功。

### 5.5 并发与确认

所有改变授权状态的事务先按 `ownerId + patternId` 锁定 `Pattern` 行，再校验授权集合。

客户端提交当前 `commercialVersion`。如果服务端版本不同，返回 `AUTHORIZATION_STATE_CHANGED`，客户端刷新授权历史后重新操作。这样可以防止用户看过旧历史并确认买断后，另一台设备已经插入新授权。

### 5.6 图案删除与统计保留

- 图案进入回收站后的 30 天内，授权记录完整保留；恢复图案时无需重建商业数据。
- 回收站中的商业历史只读；必须先恢复图案，才能新增、编辑、作废或恢复授权。
- 回收站中的授权仍计入期间收入、授权次数和排行，但不计入“当前图库状态”。看板中的排行项标记为“回收站”，并链接到对应回收站记录。
- 用户主动永久删除，或后台在 30 天后到期清理时，删除该图案的全部有效与作废授权，并清除该图案旧的商业 `ChangeLog` 载荷。同步只保留最终的最小 `Pattern` 删除墓碑，墓碑不含商业字段。
- 永久删除后，所有历史期间的收入、次数、图案数、平均价与排行允许相应减少；系统不保存独立财务账本或商业墓碑。
- 移入回收站前的确认，以及回收站中的到期提示，必须显示有效授权数量、有效授权金额和预计永久删除日期，明确说明永久删除会改变历史看板。
- 移入回收站、恢复和永久删除都与授权写操作使用同一 `Pattern` 行锁。永久删除必须在线执行；清理任务先删除 OSS 资产，再在数据库事务中锁定图案、删除授权、清除旧商业变更载荷、压缩为同步墓碑并追加最终删除事件，任一步失败均可安全重试。

## 6. 图库交互

### 6.1 右侧检查器

选中单张图案后，检查器提供“基本信息”和“商业授权”两个页签。商业授权页签包含：

- 当前商业状态
- 累计有效授权收入
- 有效授权次数
- “新增授权”主操作
- 按授权日期倒序的记录列表
- 作废记录显示开关

每条记录显示类型/领域、客户、价格和日期。编辑、作废与恢复位于记录操作菜单中。

### 6.2 授权表单

- 授权类型使用三段式分段控件。
- 普通授权和领域独占显示领域组合框；全局买断隐藏领域控件。
- 领域组合框搜索系统和自定义领域，并提供“创建自定义领域”命令。
- 金额输入以元显示，只接受非负整数或最多两位小数；提交时转换为整数分，禁止使用浮点数直接计算。
- 授权日期默认今天，用户可修改，但不得晚于服务端当前日期。
- 客户名称必填，备注可选。
- 独占/买断二次确认列出已有有效授权数量和最近记录。

自定义领域集中在 `/settings` 的“授权领域”区管理；系统领域带锁定标识，自定义领域可归档。

### 6.3 图库摘要与筛选

图案卡片只显示一个最高优先级状态：

```text
全局买断 > 含领域独占 > 普通授权 > 未授权
```

卡片可附有效授权次数和累计收入，不堆叠每个领域标签。图库新增商业状态与授权领域筛选。点击看板中的领域或图案会返回带相应筛选条件的 `/library`。

## 7. 数据看板

新增 `/dashboard`，入口位于左侧主导航，不新增独立授权台账页。

### 7.1 筛选

- 默认时间范围为当前自然年。
- 可选当前年、近 12 个月、全部时间和自定义起止日期。
- 可按授权领域和授权类型筛选期间指标。
- 起止日期均包含当天。
- “当前图库状态”不受时间范围影响，并始终标注“截至今日”。
- “当前图库状态”只统计 `ready` 等当前图库内的图案，不包含回收站或已永久删除的图案。

### 7.2 期间指标

- 授权收入：有效记录 `priceFen` 之和。
- 授权次数：有效授权记录数，包含 0 元记录。
- 授权图案数：有效授权的不同 `patternId` 数量。
- 平均授权价：有效授权收入除以有效授权次数。
- 收入趋势：当前自然年和近 12 个月按月；全部时间跨度不超过两年时按月、超过两年时按年；自定义区间不超过 62 天时按日、超过 62 天且不超过两年时按月、超过两年时按年。
- 当前自然年按 1 月 1 日至今天与上年同期比较；近 12 个月与此前 12 个月比较；自定义范围与其紧邻的前一等天数区间比较。
- 对比周期无数据时显示“暂无对比”。
- “全部时间”没有可定义的前一周期，不展示周期对比。

### 7.3 当前图库状态

每张图案只进入一个状态桶：

1. 有有效全局买断 → 全局买断
2. 否则有有效领域独占 → 含领域独占
3. 否则有任意有效普通授权 → 普通授权
4. 否则 → 未授权

### 7.4 排行

- 授权领域排行按有效授权次数排序；全局买断没有领域，不进入该排行。
- 收入最高的图案按有效授权金额合计排序。
- 系统领域和有效自定义领域按字段 ID 聚合；已归档自定义领域以名称快照显示。
- 并列时以收入、最近授权日期和名称作为稳定次级排序。
- 回收站图案在排行中保留并标注状态；图案永久删除后，其授权和排行项一并消失。

### 7.5 空状态

- 无收入显示 `¥0`。
- 无授权时展示明确空状态，不绘制伪造趋势线。
- 没有对比基数时不显示无穷百分比。

## 8. API 与数据流

### 8.1 API

- `GET /api/patterns/:patternId/authorizations`：游标分页读取授权历史。
- `POST /api/patterns/:patternId/authorizations`：新增授权。
- `PATCH /api/authorizations/:authorizationId`：编辑授权。
- `POST /api/authorizations/:authorizationId/void`：作废。
- `POST /api/authorizations/:authorizationId/restore`：恢复。
- `GET /api/authorization-fields`：读取系统与当前用户的有效领域。
- `POST /api/authorization-fields`：创建自定义领域。
- `DELETE /api/authorization-fields/:fieldId`：归档自定义领域。
- `GET /api/dashboard/authorizations`：读取看板聚合数据。

所有端点通过 Zod 校验，忽略客户端传入的 owner 标识，并从 Auth.js 会话获取 `ownerId`。

### 8.2 新增授权流程

1. 客户端加载当前 `commercialVersion` 和授权摘要。
2. 用户填写表单；客户端只做即时格式反馈。
3. 服务端解析人民币字符串为整数分，并开始数据库事务。
4. 服务端按 owner 和 pattern ID 锁定图案行。
5. 服务端比较 `commercialVersion`，校验领域、互斥状态和历史确认标志。
6. 服务端插入授权、递增 `commercialVersion`、追加 `ChangeLog` 并提交。
7. 客户端使当前图案、图库查询和看板查询失效并重新获取。

### 8.3 看板查询

看板由 PostgreSQL 聚合查询直接生成，不维护统计汇总表。查询模块返回已经格式化为传输对象的整数分/十进制字符串，JSON 中不直接序列化 JavaScript `bigint`。

目标规模为 10,000 张图案和 100,000 条授权记录。上线前使用 `EXPLAIN ANALYZE` 验证时间范围、领域排行、当前状态和图案排行查询命中预期索引。

## 9. 错误与权限

稳定错误码：

| 错误码 | 含义 | 客户端处理 |
| --- | --- | --- |
| `AUTHORIZATION_FIELD_LOCKED` | 领域已独占 | 刷新历史并显示冲突记录摘要 |
| `PATTERN_BOUGHT_OUT` | 图案已全局买断 | 禁用新增并显示买断记录 |
| `PATTERN_NOT_ACTIVE` | 图案不处于可授权的 `ready` 状态 | 刷新图案；回收站图案提示先恢复 |
| `AUTHORIZATION_HISTORY_CONFIRMATION_REQUIRED` | 独占/买断前存在历史授权 | 打开二次确认 |
| `AUTHORIZATION_STATE_CHANGED` | 商业版本过期 | 刷新后要求用户重新确认 |
| `AUTHORIZATION_RESTORE_CONFLICT` | 作废记录已不能恢复 | 保持作废并展示当前冲突 |
| `AUTHORIZATION_FIELD_EXISTS` | 自定义领域重名 | 聚焦领域输入并建议现有项 |
| `AUTHORIZATION_FIELD_ARCHIVED` | 选择了已归档领域 | 刷新领域选项 |
| `AUTHORIZATION_PRICE_INVALID` | 金额非法 | 保留表单并定位金额字段 |

跨用户读取、编辑、作废、恢复统一返回 404，不暴露记录存在性。日志只记录 request ID、owner ID、pattern ID、authorization ID 和错误码，不记录客户名称、备注或完整商业数据。

## 10. 在线与缓存边界

- 授权与领域写操作必须在线。
- 离线时可以显示最近一次已加载的图案商业摘要，但必须标记为可能过期。
- 离线时禁用新增、编辑、作废、恢复和看板刷新。
- 商业写操作不进入 Dexie outbox，避免金额和独占冲突采用客户端时钟合并。
- 在线变更通过 `ChangeLog` 和查询失效让其他设备收敛。

## 11. 视觉设计系统

采用已确认的“石墨靛蓝”方向：大面积使用中性白/黑，靛蓝只承担交互强调，不给图案缩略图叠加品牌色滤镜。

### 11.1 主题

用户可选择 `跟随系统 | 浅色 | 夜间`。偏好保存在用户设置中，本地保留最近值以避免首屏闪烁。

服务端在 `User.themePreference` 保存 `system | light | dark`；浏览器本地镜像只负责首屏预设，登录后的服务端值是最终偏好。

浅色核心色：

- 页面底：`#F6F7F9`
- 主表面：`#FFFFFF`
- 主文字：`#202227`
- 次文字：`#6F7480`
- 边界：`#E1E4E9`
- 主操作/选择：`#3B5DA8`
- 主操作悬停：`#304F95`

夜间核心色：

- 页面底：`#090B0F`
- 主表面：`#0F1217`
- 抬升表面：`#151922`
- 主文字：`#ECEEF4`
- 次文字：`#9AA0AD`
- 边界：`#292E38`
- 主操作/选择：`#7893DC`
- 主操作悬停：`#8CA4E5`

浅色状态色：普通授权绿 `#2F6F4E`、领域独占暗金 `#80651E`、全局买断/危险红 `#A34747`。夜间状态色：普通授权绿 `#6FB58B`、领域独占金 `#D2B45B`、全局买断/危险红 `#DE7B7B`。未授权使用中性灰，选中与通用信息状态使用靛蓝。

状态色必须同时配合文字或图标，不能只依赖颜色传达授权类型或错误；所有前景/背景组合在对应主题下通过 WCAG AA 对比度检查。

### 11.2 排版与表面

- 字体栈：`Inter, PingFang SC, system-ui, sans-serif`。
- 紧凑工作台正文以 13–14 px 为主，面板标题 15–18 px；不使用英雄式大标题。
- 字距固定为 0，不使用负字距或随视口变化的字号。
- 普通控件圆角 4 px，面板和对话框最多 6 px。
- 页面区块不做漂浮卡片；边框和留白建立层级，阴影只用于对话框、菜单和临时浮层。
- 不使用渐变、装饰光斑或大面积靛蓝背景。
- 动效集中在 120–180 ms 的状态切换，并尊重 `prefers-reduced-motion`。

### 11.3 图表

- 收入趋势以靛蓝为主系列。
- 图库状态使用中性灰、绿色、靛蓝和暗红，浅色与夜间模式分别校验对比度。
- 图表同时提供数值、标签和可访问文本，不以悬停作为唯一取数方式。
- 透明图案使用中性棋盘格，夜间模式不改变图片色彩。

## 12. 测试策略

### 12.1 单元测试

- 人民币字符串到整数分的转换：`0`、`0.1`、`0.10`、大额和非法小数位。
- 领域名称规范化、系统/自定义冲突和归档行为。
- 商业状态优先级。
- 收入、次数、平均价、同比/周期对比空基数、趋势粒度和日期边界。
- 明暗主题 token 完整性。

### 12.2 PostgreSQL 集成测试

- 同领域多条普通授权。
- 领域独占和全局买断互斥。
- 两个并发事务尝试普通授权/买断时只有合法事务成功。
- 授权写入与移入回收站或永久删除并发时，只有符合最终图案状态的事务成功。
- 编辑授权类型和领域时重新校验。
- 作废解除限制，恢复遇到新冲突时失败。
- 删除自定义领域后历史快照仍可查询和统计。
- 跨用户读写返回相同 404。
- 看板聚合排除作废记录并包含 0 元授权次数。
- 回收站图案保留期间商业统计、但不进入当前图库状态；永久删除后授权与历史统计同步移除。

### 12.3 组件与端到端测试

- 授权类型切换时领域字段正确出现/隐藏。
- 创建自定义领域并立即选择。
- 独占/买断二次确认和过期版本刷新。
- 图案卡片状态、商业筛选和看板下钻。
- 作废记录后收入与状态同步回退。
- 含授权图案移入回收站时显示商业数据删除警告，恢复后授权不丢失。
- 永久删除含授权图案后，期间指标、趋势和排行按确认口径回退。
- Chromium 与 WebKit 下浅色/夜间主题无文字溢出、图表不可读或页面横向滚动。
- 键盘可完成授权新增、编辑、筛选和看板浏览。

## 13. 验收标准

1. 一张图案可保存多条普通单领域授权，并正确累计次数和人民币收入。
2. 领域独占只阻止同领域未来授权；全局买断阻止全部未来授权。
3. 历史授权不会因后续独占、买断或领域归档而消失。
4. 作废记录不参与任何收入或当前状态统计；恢复必须重新通过互斥校验。
5. 两台设备并发操作不能绕过独占或买断规则。
6. 看板日期筛选、领域排行、图案排行和当前状态符合本设计口径。
7. 10,000 张图案、100,000 条授权的种子数据下，聚合查询有索引支持且交互无明显冻结。
8. 用户无法通过猜测 ID 读取或修改其他用户的授权数据。
9. 浅色以白色为主体、夜间以近黑色为主体；两种主题均通过关键文本和控件的 WCAG AA 对比度检查。
10. 图案永久删除会删除其全部授权，历史看板按剩余有效授权重新计算；执行前界面明确展示影响。

## 14. 与主项目的实施关系

商业授权是独立业务子项目，但依赖主项目的用户、图案、鉴权、数据库和工作台外壳。

推荐实施顺序：

1. 完成主项目基础、鉴权、`Pattern` 与基础图库。
2. 实现授权领域、授权事务规则和图案检查器。
3. 实现图库商业摘要与筛选。
4. 实现数据看板与索引性能验证。
5. 完成浅色/夜间主题视觉验收。

该子项目不依赖 PSD/AI 预览或完整离线同步，可以在基础图库稳定后独立交付和测试。
