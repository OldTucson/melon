# Melon 全局 UI 系统重设计

日期：2026-10-28

状态：已确认

## 背景

`melon` 已具备私有图案库、文件夹与标签、商业授权、数据看板、回收站、上传、以图搜图和配色搜索等完整工作流，但当前视觉主要由一个约 4,700 行的全局 CSS 文件承载。界面功能清楚，组件却缺少稳定的层级、间距、表面、交互状态和品牌语言，导致不同页面之间质感不一致，无法充分体现面向设计师用户的产品定位。

本次改造服务于近期面试展示，因此优先产出一个可完整演示、全页面一致、视觉完成度高的版本。只引入能够直接改善观感、易用性、稳定性或真实复用度的抽象，不为了构建理想化组件库而延迟可见成果。

## 已确认方向

- 视觉风格：`Gallery White`，接近独立画廊与设计杂志，但保持高效工具属性。
- 信息密度：桌面默认高密度扫描，MacBook 14 英寸主视口稳定显示五列图库。
- 导航结构：自适应折叠栏，桌面默认展开，可收成图标栏并记住本地偏好；平板和手机使用抽屉。
- 强调色：`Acid Lime`，只用于主操作、选中、焦点和关键图表，不大面积铺色。
- 主题范围：浅色与深色模式同时完整重做，并继续支持系统主题。
- 改造边界：允许重组信息层级、导航、控件布局和交互方式，但保持现有功能、URL、权限、数据和 API 合约兼容。
- 设备优先级：桌面与 MacBook 14 英寸优先；平板完整可用；手机保留全部功能并使用抽屉、底部面板和单列布局。

## 目标

- 建立简约、易用、有质感、高雅且适合设计师日常使用的统一视觉语言。
- 让图库图片、主色色卡和商业状态成为第一视觉层级，减少无意义容器和重复边框。
- 统一所有页面与浮层的字体、色彩、间距、圆角、阴影、焦点和交互反馈。
- 保持高密度素材扫描效率，同时提升名称、格式、授权和操作的辨识度。
- 在浅色和深色主题中保持一致的信息层级与可访问对比度。
- 保持现有虚拟化、查询、上传和搜索性能边界。
- 形成适合面试演示的完整视觉闭环，而不是只美化图库首页。

## 非目标

- 不修改数据库结构、API 合约、权限模型或业务规则。
- 不更换 React、Next.js、Radix、TanStack Query 或 TanStack Virtual。
- 不迁移到新的大型 UI 组件库，不引入外部字体服务。
- 不重写上传、预览、图像搜索、配色搜索、授权或删除流程。
- 不创建营销首页、装饰性插画、渐变背景、大圆角卡片或嵌套卡片布局。
- 不为了拆分全部旧 CSS 而推迟可展示版本；只拆分本次改造直接涉及的基础层和共用组件层。

## 视觉系统

### 颜色

浅色主题以纯白、瓷白和冷雾灰构成画布与表面，墨黑负责主要文字和结构。深色主题使用近黑画布、深炭表面和灰白文字，重新定义边界与状态，不做浅色变量的机械反相。

`Acid Lime` 是唯一品牌强调色，建议基准值为 `#D9EF52`。它只用于：

- 主按钮及其必要的悬浮、按下状态。
- 当前导航、选中图案和已选色块的关键标识。
- 键盘焦点与需要立即识别的图表重点。
- 少量品牌细节。

成功、警告、危险和商业授权状态继续使用独立语义色，不能用品牌黄绿替代。图案自身的色卡不受品牌色限制。

### 字体

- 正文、控件、表格和数据继续使用本地无衬线系统字体：`Inter`、`PingFang SC`、`system-ui`。
- 页面级标题使用本地衬线字体：`Georgia`、`Songti SC` 及系统 serif fallback。
- 衬线字体只承担页面层级和少量品牌表达，不进入按钮、表格、卡片元数据或高频操作区。
- 不使用负字距，不按视口宽度缩放字号。

### 尺寸与表面

- 顶栏高度 56px；展开侧栏宽度约 216px；折叠侧栏宽度约 60–64px。
- 控件以 32px 和 36px 两档高度为主，图标按钮保持稳定方形尺寸。
- 常规圆角控制在 4–8px；素材图片、输入框和弹窗遵循同一半径体系。
- 页面区块不使用浮动卡片。边框、留白和排版承担分区职责。
- 阴影只用于弹窗、菜单、拖拽层和需要建立浮层关系的元素。
- 所有固定格式元素使用稳定尺寸、网格轨道或纵横比，避免状态切换导致布局跳动。

### 交互状态

按钮、图标按钮、输入、筛选、导航、卡片、色块和表格行必须覆盖：默认、悬浮、按下、选中、禁用、加载、错误和键盘焦点。焦点轮廓在浅色和深色主题下都必须清晰，不能只依赖颜色区分状态。

## 信息架构与工作区骨架

### 顶栏

顶栏承载品牌、全局搜索、以图搜图入口、同步状态、上传主操作和账号入口。主搜索保持中心位置，上传使用品牌强调色，账号信息在中等宽度以下收成图标。

### 自适应侧栏

展开状态显示导航名称、文件夹树、标签和工作区入口。用户可一键折叠为图标栏，偏好保存在浏览器本地，不新增数据库字段。桌面默认展开；中等宽度可默认折叠；平板和手机改为覆盖式抽屉，关闭后释放全部画布宽度。

折叠不能改变路由和筛选语义。图标需要 tooltip，当前页面同时使用位置、形状和颜色表达，不只依赖黄绿背景。

### 主内容区

页面标题使用衬线字体，眉题、数量、同步状态和辅助文案使用小号无衬线字体。筛选工具栏以单条紧凑水平带呈现，不包进额外卡片。长列表和虚拟化区域继续占据剩余高度，不引入页面级双滚动。

## 共用组件体系

本轮建立轻量共用层，不迁移到新组件库。优先统一以下真实重复元素：

- 主按钮、次按钮、危险按钮、图标按钮和按钮组。
- 文本输入、搜索框、原生选择框、Radix 菜单与组合框。
- 分段控制、复选框、开关和主题选择。
- 页面标题、区块标题、状态标签、提示条和空状态。
- 弹窗、抽屉、下拉菜单、tooltip 和确认流程。
- 加载骨架、内联错误、重试状态和禁用反馈。

现有 Lucide 图标和 Radix 行为继续使用。共用组件只抽取已经在多个页面重复且状态复杂的部分；页面专用结构留在所属 feature 内，避免为了统一而制造难理解的通用 API。

## 页面设计

### 图库

- `1512 × 982` 主视口默认五列；较宽屏最多六列，较窄桌面按可读宽度降为四列。
- 卡片不使用厚重背景容器。正方形图片、3–5 个主色色块、名称、格式、大小和商业状态构成连续垂直层级。
- 高频操作在悬浮、键盘聚焦或选中时清晰出现；移动端始终可访问，不依赖 hover。
- 选中状态使用明确边框、勾选和轻量黄绿标识，不能大面积染色覆盖图案。
- 筛选、排序、视图模式和结果数量保持紧凑，支持现有 URL 查询状态。
- 虚拟化网格、无限加载和列表模式继续保留。

### 检查器、以图搜图与配色搜索

- 桌面检查器保持右侧工作面板，强化图片、色卡、元数据、标签、文件夹和商业授权的分组层级。
- 以图搜图继续使用聚焦弹窗，上传区、裁剪区、搜索状态和结果分组使用同一控件与提示体系。
- 配色查询条明确展示已选颜色、移除动作、结果数和清除入口；色块保留实际颜色作为第一信息。
- 窄屏检查器与搜索流程改为全屏或底部面板，避免在小画布中嵌套弹窗。

### 上传与批量操作

- 上传主操作位于顶栏；拖拽覆盖层、文件选择、上传队列和失败重试使用一致状态样式。
- 批量操作栏固定在不会遮挡图案内容的位置，突出选择数量和主要操作，危险操作与普通操作分离。

### 数据看板

- KPI 使用紧凑指标带，不制作装饰性大卡片。
- 趋势图、当前状态和排行使用全宽分区或清晰网格，减少重复边框。
- 图表以中性灰为基础，品牌黄绿只强调当前重点；授权语义色保持独立。
- 筛选器与日期范围在 MacBook 14 英寸同一标题行内稳定排布，窄屏换行而不重叠。

### 设置

- 设置页使用受控内容宽度和分区式布局，通过标题、说明、分隔线与留白组织内容。
- 外观、授权领域、图像索引和法律信息保持现有顺序与语义。
- 二元设置使用开关或分段控制，选项集合使用菜单，避免将所有操作做成同形文本按钮。

### 回收站

- 文件夹批次和图案批次使用可扫描行布局，突出名称、数量、过期时间和商业影响。
- 恢复是普通操作，永久删除使用危险色与确认弹窗；处理中、失败和可重试状态清晰区分。
- 空回收站、载入失败和离线删除限制使用统一空状态与提示条。

### 登录、改密与法律页面

- 认证页面保持专注，不增加营销内容。品牌、标题、表单、错误和法律链接使用同一视觉系统。
- 登录面板控制在适合键盘输入的宽度，不嵌套装饰卡片。
- 法律页面优先可读性，使用窄文本栏、清晰标题层级和稳定段落节奏。

## 数据流与兼容性

现有 Server Components、React Query、Zustand、URL 查询参数、上传协调器、虚拟化列表和 API 客户端不变。视觉组件通过现有 props 和 store 获取状态，不复制业务状态，也不引入第二套筛选或选择来源。

侧栏展开状态是唯一新增的纯界面状态，保存在 `localStorage` 并在客户端挂载后应用。无本地偏好时按视口选择安全默认值。读取失败时回退到展开状态，不影响导航。

现有路由、查询参数、下载链接、权限检查、错误码和确认流程保持兼容。必要的 DOM 调整必须保留可访问名称、角色和现有测试能够依赖的业务语义。

## 加载、错误与空状态

- 首次加载使用与最终内容同尺寸的骨架，避免工具栏、网格和图表跳动。
- 后台刷新保留已有内容，只在所属区域显示轻量更新状态。
- API 错误显示在对应功能区域，保留具体可执行的重试入口。
- 全局 toast 不替代内联错误；只有跨区域完成反馈才允许使用短暂通知。
- 危险操作继续使用明确确认弹窗，说明影响范围和不可逆性。
- 图搜或色搜不可用时不影响普通图库浏览。

## 响应式与主题

主要验收视口为 `1512 × 982`，同时覆盖 `1280 × 800`、平板和手机窄屏。

- 桌面：完整顶栏，自适应侧栏，四至六列图库，右侧检查器。
- 平板：折叠栏或抽屉，三至四列图库，检查器覆盖显示。
- 手机：单列或双列图片网格，筛选进入抽屉，检查器与搜索使用全屏流程。

浅色、深色和系统主题共享语义令牌名称，但使用独立颜色值。深色主题必须逐项检查图片背景、色卡边界、输入、菜单、图表、危险状态和禁用状态，不允许只替换页面背景。

## 实施策略

为了尽快形成面试可展示成果，实施遵循“先统一可见表面，再清理内部重复”的顺序：

1. 建立设计令牌、基础元素和共用交互状态。
2. 重做工作区骨架、顶栏、自适应侧栏和页面标题层级。
3. 完成图库卡片、工具栏、检查器、色搜、图搜和上传流程，这是首个可演示里程碑。
4. 覆盖数据看板、设置、回收站、登录、改密、法律页面和共用浮层。
5. 删除被新系统替代的重复样式，保留尚未涉及的稳定业务样式。

每个阶段都保持应用可运行。不会先花大量时间将全部 CSS 完美分层后才开始页面改造。若抽象与可见成果发生冲突，优先选择可维护的最小抽象和可演示结果。

## 测试与验收

### 自动化

- 保持现有单元、集成和 E2E 测试通过。
- 为侧栏展开、折叠、本地偏好、桌面默认值和移动抽屉增加组件测试。
- 为新增共用控件覆盖主要状态、键盘焦点和可访问名称。
- 保持图库虚拟化、选择、检查器、图搜、色搜、上传、授权和删除行为测试。
- 执行类型检查、lint、生产构建和完整测试套件。
